# dynacard-cards/ — real card inputs for the dynacard-diagnostics demo

The dynacard demo report (`compose-dynacard.py` → `proto-reports/dynacard-diagnostics.report.html`)
plots two **real** rod-pump dynamometer cards generated by digitalmodel's
`artificial_lift` synthetic engine and diagnosed by its classifiers. The cards are
checked in here (not regenerated each run) because the upstream classifiers are
mis-calibrated and seed-sensitive — see `../QA-HICCUPS.md` item 10.

| File | Mode | Classifier | Diagnosis | Note |
|---|---|---|---|---|
| `pt-card.json` | PUMP_TAGGING (seed 711) | shipped ML | Pump tagging, 100.0% | clear bottom-of-stroke load spike |
| `fp-card.json` | FLUID_POUND (seed 721) | legacy threshold | Fluid pound, rule-based | truncated card / incomplete fillage |

## Regenerate (run from the digitalmodel checkout)
```bash
cd /mnt/local-analysis/.deckhand-compute/digitalmodel
# Pump tagging (shipped ML classifier, router-direct):
PYTHONPATH=src uv run --with pyyaml python <pipeline>/dynacard-cards/gen-card.py PUMP_TAGGING 711 /tmp/pt-card.json
# Fluid pound (forces the legacy threshold classifier; seed 721 round-trips):
PYTHONPATH=src uv run --with pyyaml python <pipeline>/dynacard-cards/gen-fluidpound.py 721 /tmp/fp-card.json
```
`gen-card.py PUMP_TAGGING` may terminate inside the router; if so the card is
recovered from the saved run with `extract-pumptagging.py`. GAS_LOCK was evaluated
and rejected (card visibly contradicts its own "near-zero card area" label).

Then recompose + re-render: `bash ../update.sh dynacard-diagnostics`.
